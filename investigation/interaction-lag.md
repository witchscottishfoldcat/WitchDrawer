# 拖放与收纳盒操作卡顿排查

范围：`3933be8a` 到 `0999a62`，以及工作区已有的未提交启动优化。用户进一步确认卡顿主要发生于拖动文件、操作收纳盒。

## 已确认的阻塞路径

`DesktopBoxManager.OnWindowMouseUp` 会保存盒子位置，折叠、调整尺寸等也会保存设置。原 `DrawerService.SetSettingAsync` / `DeleteSettingAsync` 直接调用 SQLite；其异步接口并不把工作调度到后台。建盒、改名、排序、删除也有同类入口。

`4521312` 增加文件搬移日志与恢复事务，这些写入和界面设置共用数据库。因此，文件操作与界面保存重叠时，界面线程可能等待数据库写锁。这个等待路径已在隔离数据库测试中复现；尚未采集用户实际拖动过程的帧时间，不能将所有体感卡顿都归因于它。

`0999a62` 的拖动预览去重检查位于 `UpdateDragPreview`，实际窗口调用的是 `ShowDragPreview`。后者在落点没有变化时仍遍历条目、重算画布并发送属性通知。

## 本轮修改

- 将设置写入、建盒、改名、排序和删除的完整 Core 操作调度到后台，打开项目之前的数据库查询也移到后台。保留原文件恢复、搬移和删除规则。
- 设置写入与删除共用异步队列，避免快速连续操作后旧值覆盖新值，并正确释放取消操作占用的队列。
- 在实际调用的网格/封面预览入口去重；重复隐藏也直接返回。仅改变预览时不再逐项重置图标位置。
- 保留进入任务前已有的启动快照、快捷面板延迟加载等工作区改动。

## 验证

`DrawerServiceResponsivenessTests` 使用独立临时数据库，持有写事务时从独立调用线程发起操作，检查调用线程能否返回未完成的 Task，再释放写锁并等待操作成功。修复前 7 个写操作场景全部失败，修复后全部通过；另一个测试覆盖连续写入顺序、取消后恢复和写入/删除交错。

扩展拖动测试验证：相同落点不再发送属性通知；落点改变仍扩展画布；隐藏后恢复尺寸；封面预览仍能移动；原有图标实例、选择和增量刷新行为保持有效。

默认 Debug 构建受正在运行的 `WitchDrawer.App` 文件锁阻止，使用 Release 目录进行构建和全量测试。验证过程中曾出现测试临时数据库清理时的间歇性文件占用；未通过放宽断言或增加清理重试隐藏该问题。最终测试结果见任务回复。

Release 程序位于 `src/WitchDrawer.App/bin/Release/net10.0-windows/WitchDrawer.App.exe`。当前运行中的 Debug 进程仍是旧代码，需从托盘退出后启动 Release 程序才能体验此次修改。此处为本机框架依赖构建，未进行发布打包。
